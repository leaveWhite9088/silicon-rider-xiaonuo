# Silicon Rider · xiaonuo

> **一句话**：让 AI 在一个会动的模拟城市里当 8 小时外卖骑手，看它能不能把这一班的净利做到最大。

这不是笔试，是一场**会动的考试**：模型每轮看到一行"世界现状"（几点、在哪、电量、有哪些单），
回一行 JSON 调一个工具（挪车、接单、取货、送货、换电、等待）。8 小时跑完，按"赚了多少 + 干得多干净 + 决策多聪明"打分。

引擎沿用上游 **KCORES · Silicon Rider Bench**（MIT，见 `NOTICE.md`），**零修改**。
本仓库是 `xiaonuo-v1` 赛制：供给、计时、种子口径见 `docs/design.md`，版本变更见 `CHANGELOG.md`。

## 1. 三十秒看懂一局

```
06:00 开局         每 5 模拟分钟来 1–3 张新单              14:00 收工
  │                       │      │      │                    │
  ├─ 在库 6–10 单          ├─ 新增   ├─ 新增   ├─ 新增          └─ 时钟 840 封顶
  │                       │      │      │
  └─ 你：看单 → 挪车 → 接单 → 取货 → 送货（→ 电量低就换电）
```

- **时间只在你动的时候走**：查询（看地图、搜单、算距离）**不花时间**；移动/取送/换电/等待才花。
- **新单按时间到**（每 5 分钟一批）——所以你"多查几次"不会多出订单，只有"真的在跑"才会遇到新单。
- **时限从接单那一刻起算**：`deadline = 接单时刻 + timeLimit`（观察里的 `carried[].deadline` 就是真值）。
- **钱**：起步 3.65 元 + 距离费（4 km 以上每 km 1 元）+ 商品价格费（超市/药店单最肥）+ 06:00–07:00 接单 +1 元。
- **约束**：5 单 / 10 kg；电量 2%/km（满电 50 km）；换电 1 分钟 + 0.5 元。

## 2. 六个必须理解的机制

| 机制 | 规则 | 为什么会决定胜负 |
| --- | --- | --- |
| 供给 | 每 5 个**模拟分钟** 1–3 张新单；查询不推进时间 | 刷查询刷不出单；"等好单"要真花班次时间 |
| 时限 | 接单起算，不是创建起算 | 先骑到店门口再接单，空驶就不吃时限 → 才敢一车带 3–4 单 |
| 距离经济 | 4 km 以上每 km 只加 1 元，固定费 3.65 | 长单边际收益低；短单+高客单价才是"肥单" |
| 容量 | 5 单 / 10 kg | 超市单 5–10 kg，基本一车一单；餐单能凑 5 单 |
| 电量 | 2%/km，换电站 9 个 | 换电是"绕路成本"，不是"没电才去" |
| 时钟 | 840（14:00）后不再执行动作 | 最后一趟必须算好能不能在 14:00 前送完 |

## 3. 评分怎么读（满分 100 = 脚本层 70 + 决策层 30）

| 层 | 分值 | 一句话 | 公式/口径 |
| --- | --- | --- | --- |
| **A 任务成果** | 30 | 这一班赚了多少 | `30 × 净利 / 350`，封顶 30 |
| **B 执行效率** | 15 | 干得省不省 | 无效调用 5（失败+重复查询）+ **端到端耗时** 10 |
| **C 操作质量** | 25 | 干得干不干净 | 准时率 9 + 状态一致性 8 + 路径效率 8 |
| **D 决策智能** | 30 | 决策像不像聪明骑手 | 决策事实卡 × 3 位评审取中位 |

**一个例子**（假设某模型）：净利 300 元、无效调用 2%、端到端 12 分钟、准时率 0.97、0 次状态错误、路径效率 1.05

```
A = 30 × 300/350                     = 25.71
B1 = 5 × 8/10（2% → 8 级）           = 4.00（封顶 5×A/30 = 4.29）
B2 = 10 × 0.5^((12−8)/12)            = 7.94（封顶 10×A/30 = 8.57）
C  = 8.1 + 7.2 + 7.2                 = 22.50
脚本层小计                            = 60.15   （D 层另由评审给 0–30）
```

细节与分档阈值见 `docs/scoring.md`。

## 4. 设计原则

三条原则决定了这套规则长什么样：

| 原则 | 具体做法 | 为什么 |
| --- | --- | --- |
| **供给跟时间走** | 新单每 5 模拟分钟一批；查询不推进时间 | 让"多按几次工具"不再等于"多拿几张单"，供给只跟"有没有在跑"有关 |
| **计时跟任务走** | B2 用端到端（任务发出 → 结果落盘）；`t0` 必须由裁判域给（`t0_source=external`） | 写脚本代打不是免费午餐；自己给自己计时会被标成 `b2_reliable=false` |
| **种子只落承诺** | 只写 `sha256`，评分时用 `--seed` 核对；建议 3 个种子 | 防事后换种子、防同一张卷子反复背答案；真保密靠隔离 |

保住的三件事正是想测的：**随机应变**（临时改路线/电量告急）、**工具调用**（少而准地查地图/估时间）、**排布决策**（一车 3–4 单怎么排、何时收工）。

## 5. 一次完整评测怎么走

```sh
# 种子已预注册：configs/seeds.commit.json 公开承诺，明文 configs/seeds.json 由主控保管（不进库）

# 1) 起一局：一条命令；policy 就是"会玩的机器人"
node tools/harness.mjs --model Demo-s1 --seed-index 1 --policy examples/policy-greedy.mjs

# 2) 评分：按预注册序号核对承诺（不用手工传明文种子）
python src/scoring/score_run.py runs/Demo-s1 Demo --seed-index 1

# 3) 裁判素材包 → 填 D → 出榜（核对承诺 + 回放核验 + 合成总分 → 写 leaderboard/scores.md）
python src/scoring/judge_pack.py --model Demo --print
python src/scoring/finalize.py --model Demo --runs runs/Demo-s1 runs/Demo-s2 runs/Demo-s3 \
       --seed-indexes 1,2,3 --d-file leaderboard/verdicts/Demo.draft.json

# 4) 自检
pwsh tests/smoke.ps1
```

**排行在哪看**：仓库里的 [`leaderboard/scores.md`](leaderboard/scores.md)（评分自动追加，出榜脚本写最终成绩）；
推送到 GitHub 后直接看 `https://github.com/<账号>/silicon-rider-xiaonuo/blob/main/leaderboard/scores.md`。

### 两种跑法（别把自己当裁判）

| 跑法 | 谁起局/喂工具 | 谁管种子和 t0 | 谁跑官方评分 |
| --- | --- | --- | --- |
| **单代理**（agent 有 shell，自己起局自己玩，本仓库最常见） | 模型（选手） | **外部（主控/Harness）** | **外部**（或模型 `--no-record` 自检，主控复核后入榜） |
| **双代理 / 官方运行器** | 运行器 | 运行器 | 运行器 |

注意：这不是"两个人"，而是两个**信任域**。选手域可以随便操作、写脚本代打；但**种子、`t0`、官方评分、榜单**属于裁判域——选手自己握了，评测就没有意义。

## 7. 常见坑与 FAQ

**Q：不同版本的分数能混着排吗？**
不能。版本号不同（当前 `xiaonuo-v1`）就分开归档——供给、计时或锚值任一改变，分数含义就变了。

**Q：种子放在哪？**
明文在**仓库外**：`$SR_SEEDS`，默认 `<仓库>/../.sr-seeds/seeds.json`，由主控保管（本仓库只有 `configs/seeds.commit.json` 的承诺）。
跑局/评分/出榜都用 `--seed-index 1/2/3` 取序号，执行者不需要接触明文。同账号下它理论上仍能读该文件——真隔离要用另一个账号 + ACL，或由主控起局、执行者只交 policy。

**Q：怎么证明成绩没被改过？**
`node tools/verify_replay.mjs runs/<名> --seed <种子>`：用原引擎把 `trace.jsonl` 里每条调用重放一遍，与 `result.json` 逐字段对账，不一致即退出码 1、成绩无效。冒烟测试里已经带这条断言。

**Q：为什么允许写脚本代打？**
允许，但不是免费午餐：B2 从"任务发出"算起。写脚本 40 分钟 → B2 ≈ 0.9；逐轮手打 12 分钟 → B2 ≈ 8。谁更划算由权重决定，规则不偏心。

**Q：350 这个锚哪来的？**
种子 67890 的"现实路由界"≈492（每单 2d+3+1.5km 接驾的背包上界）的 71%。换种子必须 `node tools/bounds.mjs --seed X` 重标（种子 12345 → 建议 352，说明 350 不是偶然值）。

**Q：种子保密靠什么？**
`protocol.json` 只写 `sha256("sr:"+seed)`，评分时 `--seed` 核对（防事后换种子）。但引擎 RNG 是 32 位，**哈希可被暴力反推**——真正的保密只能靠"把 `src/engine/`、`runs/`、`seeds.json` 放在模型看不到的地方"。

**Q：D 层为什么不看净利？**
裁判只看脚本生成的**决策事实卡**（接单明细/排名、批次、换电、失败、履约异常），不给净利数字，防止"结果光环"。

**Q：一局多久？**
模拟 480 分钟；真实耗时取决于模型/管道，通常 2–15 分钟（端到端）。
