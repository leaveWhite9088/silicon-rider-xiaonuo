# Silicon Rider · xiaonuo

> **一句话**：让大模型在一座会动的模拟城市里跑一班 8 小时外卖（06:00–14:00）——在时间、电量、载重、时限，以及“不知道下一单从哪来”的限制下，看谁能像老骑手一样既多赚钱、又不把单搞砸。

当前赛制版本为 `xiaonuo-v1.5`；底层模拟引擎为第三方 MIT 组件（`src/engine/`，未改动核心逻辑）。最新成绩见 [`leaderboard/scores.md`](leaderboard/scores.md)。

---

## 一局怎么玩

06:00 开工（池子里先有 6–10 单）→ 每过 5 个模拟分钟刷新 1–3 张新单（11:30–13:00 午高峰翻 3 倍）→ 模型逐轮决定接单、跑路、取货、送货或换电 → 14:00 准时收工。

| 规则 | 大白话说明 |
| --- | --- |
| **出单节奏** | 只有真实行动（跑路、取送货、换电、等待）才会推进时间；查地图、查附近订单不耗时间，所以**狂刷查询刷不出新单**。 |
| **送达时限** | 从**接单那一刻**开始倒计时；池子里的待接单同时带有剩余寿命，不接也会过期消失。 |
| **车速与收入** | 车速约 1 分钟/公里（拥堵时变慢）；取货 2 分钟、送货 1 分钟、换电 1 分钟。每单配送费由起步价（3.65 元）、里程加价、餐品加价和早间补贴（06:00–07:00 接单 +1 元）组成。 |
| **体力与口袋** | 身上最多同时背 5 单、10 公斤；满电最多跑 50 公里（每公里掉电 2%），电跑干了就只能推车龟速爬；换一次电花 1 分钟、扣 0.5 元。 |
| **硬性红线** | 14:00 收班后不再执行动作（还背在身上的单白跑）；单局最多 400 轮调用；严禁写脚本代打，只能读一步观察、出一步动作。 |

## 四个维度怎么算分（满分 100）

总分 = **A 任务成果（30）+ B 执行效率（15）+ C 操作质量（25）+ D 决策智能（30）**。

| 维度 | 满分 | 评什么（说人话） |
| --- | --- | --- |
| **A 任务成果** | 30 | **到底赚了多少钱**。按 `30 × 净利 / 600` 折算（600 元为本版上限锚值），只看最终到手净利。 |
| **B 执行效率** | 15 | **干活利不利索**。分两块：① **无效调用（5 分）**：少报错、别在同一位置反复查同样的东西；② **完赛耗时（10 分）**：现实世界里跑完这一局花了多少分钟（8 分钟内满分，之后每 12 分钟减半）。为防止“躺平秒退骗快分”，只有成果分 A 达到 15 分以上时，效率分才拿满，否则按比例封顶。 |
| **C 操作质量** | 25 | **干活靠不靠谱**。分三块：① **准时与不断电（9 分）**：接下的单别超时、别被罚款、更别把电跑空到 0%；② **状态不犯糊涂（8 分）**：没到店别点取餐、没拿单别点送货、不在换电站别点换电；③ **路线别绕远（8 分）**：总行驶里程除以订单本身起止距离之和，顺路合单越巧分越高。 |
| **D 决策智能** | 30 | **脑子清不清楚**。系统把整局操作浓缩成一张隐去净利金额与模型名字的“决策事实卡”，由独立评委盲评三件事：① **挑单眼光（11 分）**、② **顺路拼单与随机应变（10 分）**、③ **电量与收班风险控制（9 分）**。 |

## 它能测出什么、测不出什么（客观边界）

这套基准不是传统的“一问一答”静态题库，它在实战中已经展现出很强的梯队区分度（实测模型总分从 47 分、60 分、65 分一直拉开到 80 分），但也有明确的适用边界：

### 它测得很准的地方
1. **长程多约束动态规划**：一局将近两百步操作，模型必须同时算清四本账——空间顺路（能不能拼单）、时间窗口（来不来得及、怎么抢午高峰）、资源底线（还剩多少电和载重）以及收班卡点（14:00 前能不能送完手头的单）。“走一步看一步”的模型很容易在后半场把电跑干或超时崩盘。
2. **上下文状态追踪纪律**：连续几十轮移动、接单、取送货之后，模型能不能清楚记得自己在哪、手里有哪几单、哪些已经取过餐，直接反映在状态分和无效调用分上。
3. **防刷分与去光环盲评**：种子保存在仓库外并做哈希承诺，出榜时用原引擎逐帧重放核验；盲评事实卡隐藏了最终赚多少钱，评委只能看每一步选单、拼单和换电合不合理，避免了“看结果给印象分”。

### 它测不到或有局限的地方
1. **不测复杂工具的参数构造能力**：场内只有 13 个固定工具，参数非常简单（基本就是一个地点编号或订单编号）。它在工具层面考的是“长程状态不乱”，而不是阅读陌生复杂接口文档、拼装多层嵌套参数或根据模糊报错自我修复的能力。
2. **完赛耗时分（10 分）会混入接口网速与慢思考成本**：耗时分统计的是从开局到收工的现实墙钟时间。这能反映“用户实际等了多久”，但对推理链很长的深度思考模型或接口受限的服务商不够友好——即便决策极佳，也可能因为思考慢在耗时项丢掉几分。
3. **路径分与全局最优偶有取舍，且三局样本怕偶发掉线**：路径分只看行驶距离比值，有时模型聪明地多跑两步去顺路换电或去热区抢大单，路径分反而会略微吃亏；同时每个模型默认测 3 个种子，若某局中途卡壳，均值波动会比较明显（总分相差 3–5 分以内时建议结合极差一起看，或加测一组）。

## 标准跑法与出榜流程

```sh
# 1) 选手逐轮打比赛（禁止任何策略脚本代打，正式成绩三局须串行跑）
node tools/session.mjs start --model Demo-s1 --seed-index 1
node tools/session.mjs act --session Demo-s1 '{"toolName":"move_to","parameters":{"targetLocationId":"node_22"}}'
node tools/session.mjs state --session Demo-s1
node tools/session.mjs stop  --session Demo-s1

# 2) 三局跑完后生成匿名盲评包（缺事实卡时会自动补算）
python src/scoring/judge_pack.py --model Demo

# 3) 评委盲评提交（只看 leaderboard/blind/<pack_id>/，评分追加到中心日志）
python src/scoring/judge_submit.py --pack-dir leaderboard/blind/<pack_id> --case-id case-01 \
  --judge-id <评委ID> --judge-model <评委模型> \
  --D1 8 --D2 7 --D3 6 --evidence "[E01] [F02]" --note "最强反证"

# 4) 一键汇总出榜（自动重算 A/B/C、核对种子哈希、逐帧回放核验，并更新排行榜）
python leaderboard/finalize.py
```

## 目录说明

```text
configs/        全局唯一配置（benchmark.json）与种子哈希承诺（seeds.commit.json）
src/engine/     第三方 MIT 模拟引擎（只读）
src/client/     比赛驱动与车速/订单分布调节
src/scoring/    客观分计算、事实卡生成、盲评打包与汇总出榜
tools/          会话桥、逐帧回放核验、时间重叠审计、种子生成与上限测算
tests/          一键冒烟测试与计分/计时/车速/分布单元测试
docs/           详细规则（protocol.md）、计分公式（scoring.md）与设计说明（design.md）
runs/           各模型每局的轨迹、结算与事实卡（过程数据，不进版本库）
leaderboard/    总榜（scores.md）、裁决留档（verdicts/）与盲评文件
```
