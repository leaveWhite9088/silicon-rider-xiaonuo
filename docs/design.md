# 设计说明

本文说明这套基准**是什么、为什么这样定**，以及**已知的限制**。规则细节见 `protocol.md`，计分细节见 `scoring.md`。

## 1. 测什么

在一个 480 分钟（06:00–14:00）的模拟城市班次里，模型只能通过 13 个工具看世界、做动作。
评分要回答三件事：**能不能把机会换成钱**（A）、**干得省不省**（B）、**干得干不干净**（C），
再加一层**过程是否像聪明骑手**的评审（D）。

## 2. 供给：按模拟时间，不按调用次数

- 新单**每 5 个模拟分钟**生成 1–3 张；查询工具**不推进时间**。
- 这样"多按几次工具"不会变成"多拿几张单"：**只有真正在跑，市场才会刷新**。
- 供给率因此与班次时间绑定：480 分钟 ≈ 96 批 ≈ 190–230 张单，所有选手面对同一量级的机会。

## 3. 时限：从接单那一刻起算

- `deadline = 接单时刻 + timeLimit`，观察里 `carried[].deadline` 直接给真值。
- 接单不要求人在店里，取货要求。于是"先骑到店门口、再接单、再取货"能把空驶挪到时限之外——
  这是允许的操作，也是"一车带 3–4 单"能成立的原因。
- 于是选单的核心不是"配送费最高"，而是 `fee ÷ (2×(接驾km + 送餐km) + 3分)`。

## 4. 计时：端到端

- **端到端** = 任务发给模型 → `trace/result` 落盘；看资料、写脚本、调参、对局都算在内。
- `driver_wall_seconds` 只作诊断；报告时两个数都给。
- **`t0_source`**：`external`（命令传入 `--t0`）或 `process`（驱动在进程启动时自动记录）。两者都是有效的 B2 起点，仅作诊断。
- 允许写脚本代打：它不是免费午餐，端到端会直接把 B2 打下来。

## 5. 种子：承诺 + 隔离

- 运行目录只写 `sha256("sr:"+seed)`，明文不落盘；评分时 `--seed` 核对，不匹配即作废。
- 承诺的作用是**证明种子提前定好、事后没换**，而不是保密：引擎 RNG 是 32 位 Mulberry32，
  哈希理论上可被暴力反推。
- **真正的保密靠隔离**：`src/engine/`、`runs/`、`seeds.json` 不能出现在被测模型可达的目录里。
  做不到隔离，就每个种子跑完即弃用，靠"不可预知"而不是"不可读取"保证公平。

## 6. 边界原则：留 / 限 / 堵

| 类别 | 内容 | 理由 |
| --- | --- | --- |
| **留** | 先到点后接单、合单顺路、拒单、提前换电、班末收工 | 这些都是"读懂规则后做取舍"，正是要测的能力 |
| **限** | 靠调用次数换资源、拖过 14:00 | 前者已由"按模拟时间供给"根除；后者越线只自我惩罚，可选硬拒 |
| **堵** | 预知种子/订单流、同种子调参、伪造结算 | 前两者用承诺 + 3 种子压制；伪造由回放核验挡住 |

D 层盲评：`judge_pack.py` 只输出匿名盲评包目录路径；包内不含模型名、A/B/C、运行目录或种子明文。评委通过 `judge_submit.py` 追加到中心日志 `leaderboard/reviews.jsonl`，`finalize.py` 按 mean/median 聚合；`case_id -> run` 的私有映射不交给评委。

## 7. 已知限制

| 项 | 说明 | 影响 |
| --- | --- | --- |
| 端到端含人为停顿 | 会话被中断/挂机会虚增时间 | 可用 `Σ 每轮模型推理耗时` 替代，本版先用端到端 |
| 单种子锚值 | 350 只对种子 67890 标定 | 换种子用 `tools/bounds.mjs` 重标，或用"净利 / C 界"归一化 |

C3 口径已明确为只使用 pathEfficiency = 总行驶距离 / 已完成订单取送距离之和；空驶率不参与评分，本版不再把 emptyRatio 作为评分项。

## 8. 锚值与版本

- 锚值 = "专家可达上限"的估计。标定方法：`node tools/bounds.mjs --seed <种子>` 得三档界
  （数学硬界 / 往返口径 / 现实路由界），取**现实路由界 × 0.71**，写回 `configs/benchmark.json`。
- 参考：种子 67890 → C≈492 → 锚 350；种子 12345 → C≈496 → 建议 352。
- 改动供给、计时或锚值都必须**升版本号**（本仓库当前为 `xiaonuo-v1.3.1`），不同版本的成绩分开归档，不混排。
